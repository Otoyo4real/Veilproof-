Prove an agent is good for it, without handing over its wallet

Agents are starting to pay each other: compute, invoices, OTC deals. Before a deal, the other side wants proof the agent can pay, but publishing a treasury wallet invites targeting, scams and front running. VeilProof changes the deal. An agent proves its treasury across every wallet it holds, proves the balance was HELD and not just deposited an hour ago, and carries a portable credit score any app can recompute from the same public rules. Why VeilProof

Proof a counterparty can check, without the exposure that usually comes with it.

Private by design

Only hashes go public. The wallet address travels only to the verifier you chose, in a private package, and a fresh salt per report keeps reports unlinkable.

Genuine by construction

The facts come from the chain itself, so they cannot be typed in or faked. The verifier rechecks every claim from the same data the report was built on.

Portable credit score

A deterministic score any app can recompute from the same public rules. No black box, no trust needed, and a tampered score fails verification.

How verification works

Three steps. The prover never reveals the wallet to the public; the verifier never has to trust the prover. Verification answers five separate questions, and each one gets its own status.

1 Prove Connect the wallet, sign an ownership challenge, and fetch its onchain snapshot straight from NEAR. Claims are evaluated in the browser.
2 Publish NEAR AI Cloud analyses the claims in a TEE and records an attestation reference. Only the report hashes go onchain, never the address, never amounts.
3 Verify The verifier checks the chain record, reruns every claim, and sees a separate status for the source data, the calculations, the attestation, the report integrity and the privacy, in one click, with no account and no wallet.

What it proves, and what it does not

The honest trade off, stated plainly. VeilProof is a hybrid privacy model: the public sees only hashes, the chosen verifier sees the address because they must recheck the chain, and the AI sees claim aggregates only, never the address, never transaction hashes.

ClaimWhat proves it
The data is genuineThe verifier checks the disclosed snapshot against the data hash published onchain. Onchain data cannot be typed in by the user.
The balance was held, not flashedSampled balance history at past block heights: the lowest sampled balance over the window, not a snapshot.
The wallets are all the prover'sEach linked wallet proves ownership with a transfer to the primary wallet, or by signing a link message with its key, no transfer, no gas.
The credit score is realThe score is deterministic (score v2, published rules): the verifier recomputes it from the same snapshots and the same windows. A tampered score fails verification.
The underwriting opinion is honestNEAR AI Cloud TEE attestation is checked server side when the analysis runs: the DCAP quote, the nonce, the response signature and the measurements. This page does not recheck them, so the attestation status is shown on the verifier page. The verdict is advisory, a thin score can never support a lend, by a deterministic guard.
The report was not alteredSHA 256 report hash anchored on NEAR; tampering fails verification.
The wallet belongs to the proverThe prover signs a challenge with the wallet key; the publish transaction records the signer as owner.
The wallet address stays privateOnly a hash commitment is published. The address travels only in the private disclosure package to the verifier the prover chose.
Anything offchainNothing. VeilProof only ever makes claims about onchain data.

Who uses it

Agent treasuries An agent proves it can settle a deal, across every wallet it holds, with a sustained balance and a portable score, without publishing the treasury addresses that would invite targeting.
Agent to agent credit A service agent checks a client agent's score and a NEAR AI underwriting opinion before extending compute or credit, the score is recomputable, so no one has to trust the claimant.
Lending A borrower proves balance, sustained history and a clean record to a lender without handing over the wallet that holds everything.
Grants and OTC deals A grantee proves onchain activity to a committee, or a counterparty proves it can settle before a deal is struck, the proof, not the address, changes hands.
